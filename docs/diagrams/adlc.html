01 · Build14typed tools

A harness with tools, and no keys to the vault

  • Any model as the agent: Claude, any OpenAI-compatible model, or any MCP client through bun run mcp
  • The toolbox is the whole reach: assess_incident pay_invoice_by_card and twelve more. Never create_transfer approve
  • Policy as code: the Commander lists what is allowed; thresholds live in code the model never sees
  • Untrusted mail goes through a quarantined reader that returns booleans, never text
02 · Test57/57attacks held

Evals that try to steal the money

  • 639 tests, and a red team of 57 ways to pay twice, pay the wrong party or rewrite history bun run redteam
  • 100 mutations: each guard removed once, every one caught bun run mutate
  • Simulation, end to end: a simulated Airwallex and eight broken invoices, worked by the agent over many turns smoke:offline
  • Scale: 100 mixed incidents, then a check against the bank: at most one live payout each
03 · Deploy2runtimes

Durable, human in the loop, sandboxed

  • Durable execution: the intent is sealed before every network call, and a crash resumes by its request ID. Tested with kill -9
  • Human in the loop: risky money and every Visa card wait for a named person’s written signature
  • Sandboxes: the offline simulator and the Airwallex sandbox. Tessera Live on EC2 seals each workspace’s keys; the public demo runs with no egress at all
04 · Monitoreverycall sealed

The trace is a hash-chained ledger

  • Every tool call, refusal, webhook and card charge is an event chained to the one before verifyChain
  • Signals: policy refusals, bank-side reassessments, a card charge proved against its signed terms
  • Feedback and dashboards: the queue is where people answer the agent; the control room tracks what is stopped, replaced and certified
  • Outcomes are certified against Airwallex’s own wallet lines
